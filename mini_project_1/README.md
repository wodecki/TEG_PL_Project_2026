# Miniprojekt 1: fundament wiedzy

**Cel:** przygotować wyszukiwanie semantyczne, czyli wyszukiwanie według znaczenia, w 18 dokumentach Kovalo, oszacować miesięczny koszt asystenta i sprawdzić połączenie z dużym modelem językowym (ang. large language model, LLM).
**Czas:** około 3 godzin. **Framework:** LangChain, te same komponenty co w przykładach RAG z kursu.

## Jak pracować

Każde polecenie uruchamiaj z katalogu głównego repozytorium, czyli z folderu, w którym znajduje się `config.yaml`.

Raz na początku:

```bash
uv sync
cp .env.example .env        # potem dodaj klucz OpenAI: zobacz „Podłącz swój LLM” niżej
```

Kroki 1–5 **nie wykonują płatnych wywołań API i nie potrzebują klucza**: wektorowe reprezentacje tekstu (ang. embeddings) są odczytywane z dołączonej pamięci podręcznej (ang. cache). Krok 6 wykonuje jedno prawdziwe wywołanie twojego LLM-a (polecamy OpenAI `gpt-5.4-mini`).

Przy pierwszym uruchomieniu kroku 2 (twojego kodu albo jego testów) `tiktoken` pobiera dane tokenizera, więc wtedy potrzebne jest połączenie z internetem. Dane zostają na dysku i kolejne uruchomienia działają offline.

Potem dla każdego kroku:

1. Otwórz plik kroku w `mini_project_1/src/`. Na górze znajdziesz **CEL**, przykładowy **WYNIK**, **WYMAGANIA** sprawdzane przez testy, **ZALECANE NARZĘDZIA** i polecenie uruchamiające test.
2. Napisz kod pod `# TODO`. Wybierz czytelną organizację kodu: możesz użyć jednej funkcji lub kilku funkcji pomocniczych. Sprawdzane są tylko wynik i wymagania.
3. Uruchamiaj test kroku i poprawiaj kod, aż test przejdzie.
4. Uruchom `uv run python mini_project_1/src/check.py`. Program podpowie, który krok jest następny.

## Podłącz swój LLM

**Polecamy OpenAI `gpt-5.4-mini`.** `config.yaml` już go wskazuje (`provider: openai`, `model: gpt-5.4-mini`), więc wystarczy wpisać klucz do `.env`:

```
OPENAI_API_KEY=sk-...
```

Jedno uruchomienie kroku 6 kosztuje ułamek centa. Dlaczego OpenAI, ile kosztuje cały projekt i co zrobić, jeśli nie chcesz płacić: „Który LLM?” w głównym [README](../README.md).

**Inne możliwości (bez gwarancji).** Kod działa też z poniższymi dostawcami. Twoje odpowiedzi i koszty będą inne niż w przebiegu referencyjnym, małe modele lokalne częściej zawodzą, a `first_llm_call.py` o tym przypomina. Dema z kursu w `2. Models/1. LLMs` pokazują obie możliwości.

| | Koszt | `config.yaml` | `.env` |
|---|---|---|---|
| **OpenRouter**: jedno konto do modeli wielu dostawców | płatność za tokeny | `provider: openrouter`<br>`model: openai/gpt-5.4-mini` (nazwy mają postać `dostawca/model`, zobacz openrouter.ai/models) | `OPENROUTER_API_KEY` |
| **Ollama**: model na twoim komputerze | za darmo | `provider: ollama`<br>`model: gemma3:4b` | nic |

Ollama: zainstaluj ją ze strony [ollama.com](https://ollama.com), a potem raz uruchom `ollama pull gemma3:4b` (około 3,3 GB).

**`OPENAI_API_KEY` jest potrzebny tylko przy `provider: openai` oraz do `try_search.py`**, który na żywo liczy w OpenAI embeddingi twoich własnych pytań, nawet gdy twój LLM działa lokalnie. Cała reszta Miniprojektu 1 działa bez niego.

## Przybornik

Przykłady pokazują działanie poszczególnych narzędzi na fikcyjnych danych. **Nie są** rozwiązaniem: dopasuj folder, typy plików, ustawienia i nazwy do swojego kroku.

### Krok 1: wczytywanie plików i dołączanie metadanych

```python
from pathlib import Path
from langchain_community.document_loaders import DirectoryLoader, TextLoader

loader = DirectoryLoader("notes/", glob="*.txt", loader_cls=TextLoader,
                         loader_kwargs={"encoding": "utf-8"})   # przekazywane do każdego TextLoadera
docs = loader.load()                        # jeden Document na każdy plik .txt
docs[0].page_content                        # 'Spotkanie o 10:00 ...'
docs[0].metadata                            # {'source': 'notes/monday.txt'}
Path(docs[0].metadata["source"]).name       # 'monday.txt'

docs[0].metadata = {"author": "Anna", "source": "monday.txt"}  # metadata to zwykły słownik: podmień go

from helpers.catalog import load_catalog
catalog = load_catalog(config.path("paths.corpus_catalog"))
catalog["POL-004_travel_and_expenses.md"]["owner"]             # 'Kierownik finansowy'

sorted(docs, key=lambda d: d.metadata["author"])              # sortowanie według pola metadanych
raise ValueError("monday.txt: brak autora")                    # czytelny błąd podaje nazwę pliku
```

### Krok 2: tokeny i koszt

```python
import tiktoken

enc = tiktoken.get_encoding("cl100k_base")    # starszy tokenizer; config wskazuje, którego użyć
enc.encode("Dzień dobry")                     # [35, 13846, 19699, 46977, 894] - jeden identyfikator na token
enc.encode("Good morning")                    # [15571, 6693] - po angielsku dwa tokeny

config.get("cost.scenario")                   # {'questions_per_day': 400, 'working_days_per_month': 21, ...}
config.get("cost.prices_per_1m_tokens")       # {'text-embedding-3-small': {...}, 'gpt-5.4-mini': {'input': 0.75, 'output': 4.5}}
config.get("cost.reference_model")            # 'gpt-5.4-mini' - model, według którego cen liczy się oszacowanie
```

### Krok 3: podział na chunki

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(chunk_size=100, chunk_overlap=20, separators=["\n\n", " "])
pieces = splitter.split_documents(docs)       # mniejsze Documenty; każdy zachowuje metadane swojego dokumentu
pieces[3].metadata["page"] = 7                # dodanie pola metadanych do chunku

f"{'ABC-007'}#{4:03d}"                        # 'ABC-007#004' - 3 cyfry, z zerami na początku
```

### Krok 4: embeddingi z cache

```python
from langchain_classic.embeddings import CacheBackedEmbeddings
from langchain_classic.storage import LocalFileStore
from langchain_openai import OpenAIEmbeddings

model = OpenAIEmbeddings(model="text-embedding-3-large")     # ilustracja: te wywołania liczą embeddingi na żywo (płatnie);
                                                             # w projekcie każdy tekst pochodzi z cache kursu
cached = CacheBackedEmbeddings.from_bytes_store(
    model,
    LocalFileStore("my_cache/"),
    namespace="text-embedding-3-large",
    # from_bytes_store ma jeszcze dwie potrzebne opcje - zobacz WYMAGANIA w kroku 4
)
cached.embed_documents(["pierwszy tekst", "drugi tekst"])   # liczy embeddingi i zapisuje je w my_cache/
cached.embed_documents(["pierwszy tekst"])                  # teraz czyta z my_cache/, bez wywołania API
```

### Krok 5: baza wektorowa (ang. vector store) i podobieństwo kosinusowe

```python
from langchain_core.vectorstores import InMemoryVectorStore
import numpy as np

vs = InMemoryVectorStore(embedding=cached)
vs.add_documents([doc_a, doc_b], ids=["a", "b"])
vs.similarity_search_with_score("godziny otwarcia", k=2)      # [(Document, wynik), ...] od najlepszego
vs.similarity_search_with_score("godziny otwarcia", k=2,
                                filter=lambda d: d.metadata["year"] == 2025)

u, v = np.array([1.0, 2.0]), np.array([2.0, 0.5])
np.dot(u, v), np.linalg.norm(u)                               # iloczyn skalarny, długość wektora
```

## Jeśli utkniesz

<details>
<summary>Krok 3: test `test_chunks_match_the_course_cache` (chunki zgadzają się z cache kursu) nie przechodzi</summary>

Twoje chunki różnią się od ustalonych co najmniej jednym znakiem. Przekaż dokładnie trzy ustawienia z konfiguracji (`chunk_size`, `chunk_overlap`, `separators`) i nic więcej. Nie zmieniaj też tekstu dokumentów ani chunków.
</details>

<details>
<summary>Krok 3: jak numerować chunki w obrębie każdego dokumentu?</summary>

Przechowuj w słowniku następny numer fragmentu dla każdego `doc_id`. Dla każdego chunku odczytaj następny numer jego dokumentu, zapisz go w chunku i zwiększ o 1.
</details>

<details>
<summary>Krok 4: jakie są „dwie potrzebne opcje” from_bytes_store?</summary>

`query_embedding_cache` (czy pytania też mają trafiać do cache?) i `key_encoder` (jak tekst zamienia się w nazwę pliku w cache). Wartości, których masz użyć, podają WYMAGANIA w kroku 4.
</details>

<details>
<summary>Krok 5: mój kosinus różni się od wyniku z vector store</summary>

Podziel iloczyn skalarny przez iloczyn długości **obu** wektorów i zwróć `float(...)`, a nie liczbę NumPy.
</details>

<details>
<summary>Krok 6: prawdziwe wywołanie LLM-a się nie udaje</summary>

- `401` / „Incorrect API key”: klucz w `.env` jest błędny albo unieważniony. Utwórz nowy w panelu swojego dostawcy.
- `402` albo „insufficient credits” (OpenRouter), `429` „quota” (OpenAI): doładuj konto.
- „Connection refused” (Ollama): Ollama nie działa. Uruchom aplikację Ollama albo polecenie `ollama serve`.
- „model not found” (Ollama): uruchom `ollama pull <model>` z nazwą z `llm.model`.
- `temperature` wraca jako `None` przy niektórych modelach OpenAI: modele rozumujące, takie jak rodzina GPT-5, przyjmują tylko domyślną temperaturę, a LangChain pomija to ustawienie. Jest to oczekiwane zachowanie dla tych modeli.
</details>
